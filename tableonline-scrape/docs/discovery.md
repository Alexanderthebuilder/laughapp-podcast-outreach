## Confirmed facts (do not re-derive)

**URL structure:** `https://www.tableonline.fi/en/{city-slug}/{restaurant-slug}/{numeric-id}`,
with a `/book` variant at `.../{id}/book`.

Verified live examples:

```
/en/helsinki/restaurant-aoi/1528
/en/helsinki/bona-fide/1204
/en/helsinki/kitchen-and-table-helsinki/635
/en/tallinn/roof/1132
/en/tallinn/elevant/92
/en/tallinn/vegan-restoran-v/1495
```

**Estonia is on the same domain.** There is no separate `.ee` site. Finnish and
Estonian restaurants share one sequential ID space and the city slug is the
only country discriminator. The mapping is built from the site's own city
selector at run time (`phase1 discover`); `lib/cities.py` holds a seed list and
the Estonian slug set. An unmapped slug leaves `country` NULL, is written to
`failures`, and flags the restaurant `needs_review` — it is never defaulted
to FI.

**Rendering:** client-rendered SPA. `og:title`, `og:description`, `og:image`
and `canonical` are server-injected and available on a plain HTTP GET. Address,
phone, tags, review scores and Michelin flags require JS execution, which is
why Phase 2 has a separate `render` pass.

**Owner context:** TableOnline Finland Oy, part of the City-magazine group
(City.fi / Eat.fi / TableOnline.fi). Success-fee-per-cover model. Expect a few
hundred to ~1,000 venues, not thousands.

## ID routing — tested 2026-09-07

The site routes on the trailing ID and ignores the slug **for active listings**:

```
/en/x/x/92    -> HTTP 200, canonical = /en/tallinn/elevant/92
/en/x/x/1528  -> HTTP 200, canonical = /en/helsinki/restaurant-aoi/1528
/en/x/x/635   -> HTTP 404   (but /en/helsinki/kitchen-and-table-helsinki/635 -> 200)
/en/x/x/1132  -> HTTP 404   (and /en/tallinn/roof/1132 -> 404 also — deleted)
```

| Listing state | `/x/x/{id}` | Correct legacy path |
|---|---|---|
| Active | 200 | 200 |
| Deprecated / merged | 404 | 200, but degraded record |
| Deleted | 404 | 404 |

If this holds, `/x/x/{id}` enumeration returns exactly the **active**
restaurants and self-filters churned ones — which is the desired target list.

**Record 635** returns an empty `og:title` and an `og:image` pointing at
`restaurant/309/`, a different ID. Both are handled as parsing guards in
`lib/tableonline.py`: a blank name is refused outright, and an image ID that
disagrees with the URL ID flags `needs_review` rather than producing a clean
lead.

## Slug-independence cross-check — NOT YET RUN

**Status: pending.** The routing rule above is inferred from four data points.
The failure mode it risks is *silent under-collection*: an active restaurant
that 404s on a wrong slug never appears and is never noticed. That must be
ruled out before the sweep is trusted.

```bash
python -m src.phase1_enumerate crosscheck --cities helsinki,tallinn
```

This renders both city listing pages, collects every real restaurant URL and
ID as ground truth, probes each through `/en/x/x/{id}`, and appends the miss
count below.

- **Zero misses** -> ID enumeration alone is safe; proceed.
- **Any misses** -> keep `/x/x/{id}` as the fast pass, then Playwright all city
  pages as a second source and union the two on `tableonline_id`.

The result is recorded here either way, and `run_report.md` reports it under
"Slug-independence cross-check".

## Fallbacks, in order

Run `python -m src.phase1_enumerate discover` first; it probes 1-3 and writes
its findings below.

1. `robots.txt` and `sitemap.xml`. If a sitemap exists it is the complete URL
   list and supersedes the sweep.
2. **DevTools discovery.** Open `https://www.tableonline.fi/en/helsinki` with
   Network -> Fetch/XHR and record every JSON endpoint. A list/search endpoint
   (check whether it takes city, tag or pagination params) plus a detail
   endpoint keyed by ID would be the best path by a wide margin — a handful of
   requests returns everything. Test whether it works with a plain `curl` or
   needs auth headers. This step is manual; `discover` covers (3) automatically.
3. Grep the JS bundles for `api`, `graphql`, `/v1/`, `/v2/` — automated by
   `discover`, reported below.
4. Playwright crawl of city index pages (`crosscheck` already does this for two
   cities; extend `--cities` to cover the rest).
5. Firecrawl `/map` on `tableonline.fi` as a second URL source, unioned with (4).

## Coverage check (Phase 1c)

```bash
python -m src.phase1_enumerate coverage --sample 50
```

Samples IDs below `max(tableonline_id)` that were *not* collected and confirms
they genuinely 404 rather than having been missed. Any uncollected ID that
returns 200 is a coverage gap and is written to `failures`. Do not skip this —
silent under-collection is the main failure mode of the whole approach.
